# 自定义动作分类管理

基线：dev / 560d6ff / TypeX 4.6.8，初始工作区干净。
本次实现用户确认的可折叠分组、批量归类、类型筛选、搜索和选择器统一方案。

## 分析和边界

问题：已有分组入口隐蔽、全部展开、动作只能逐个归类，添加和选择动作页未使用分组。
根因：分组只作为管理页元数据，选择器仍直接把可见行号作为动作数组下标。
涉及文件：公共分组模型、管理页、共享选择器、编辑器、新增的分组管理/选择页，
以及 common.h 中的折叠状态键、中英文本地化和对应回归测试。

方案：保留 linkactions、selector、group 和 linkactiongroups 协议。
新增 linkactioncollapsedgroups 存储展开状态；搜索和类型筛选使用同一显示模型。
选择器保留原有内置动作和面板分区，分类标题作为不可选的显示行。
批量操作提交前重新读取配置，按 selector 查找当前定义；分组整理不重排定义。

不修改动作执行、SpringBoard/键盘注入、其他插件或设备通信。
UI 使用主线程 UIKit 生命周期；不增加 Observer、Timer 或设备日志文件。
风险：真实 Preferences 导航、工具栏宽度、搜索呈现和拖动由系统处理，
本机桩件不能证明这些设备行为正常。

## 操作

- 顶部 +：按类型添加动作或批量添加应用。批量应用先选择目标组。
- 点击组标题展开/折叠；组头菜单在当前分组添加动作。
- 底部“分组管理”：独立新建空组、重命名、删除和拖动分组排序。
  删除分组将动作移回未分组，保持定义与已有引用。
- 顶部“选择”：点击勾选，底栏全选结果、移入分组、移出分组、删除。
  全选覆盖当前搜索/类型筛选的所有匹配动作；折叠只影响显示。
  切换搜索或类型会清空勾选；批量删除需要确认。
- “更多”：全部折叠、全部展开、调整动作顺序、分组管理。
  动作排序独立于批量勾选，只允许在同一分组拖动。
- 编辑器最后一节选择所属分组，可在草稿里创建新组；
  取消动作编辑不保存草稿动作或草稿分组。
- 搜索匹配名称、链接、类型、分组；结果显示所属分组。
  搜索期间暂时显示匹配项，退出后恢复保存的折叠状态。
- 工具栏、手势、子动作和面板选择器复用分组、搜索和类型筛选；
  保持各自的上下文限制、单选/多选和勾选回调。

## 本机验证

使用真实控制器源码和 UIKit/Preferences 测试桩，不模拟系统绘制：

- run-custom-actions-page.py：200 个动作、10 个分组，454 项控制器检查。
  覆盖首次渲染、异表注册、折叠和搜索恢复、批量归类/取消删除、
  改名/删组/空组/分组排序、动作排序、空列表重载、并发重排后的编辑保存、
  重复添加回调、单选/多选选择器、引用清理、批量应用去重和目标组失效。
- run-action-groups.py：43 项共享显示/存储模型检查。
- 批量应用、手势、面板注册、设置搜索/布局、文本及系统动作回归通过。
- 中英文字串 plutil 校验通过。

最终构建必须在本地合并后由项目根目录 ./build.sh 完成。

## 设备验收（未执行）

在 iOS 16/17 的对应 arm64/arm64e 设备上：

1. 安装匹配平台包，结束设置进程后重新打开自定义动作；
   验收空列表、仅未分组、200 动作/10 分组，并重复进入页面。
2. 折叠多组，结束设置后重新打开，展开状态应保留。
   搜索折叠组名称能找到动作；清空搜索后恢复原状态。
3. 按类型筛选并全选，移入另一组，数量应正确，已有工具栏和手势动作应可执行。
   切换筛选应清空勾选，取消删除应不修改数据。
4. 新建/改名/删除/排序分组，动作不能丢失；
   调整组内动作顺序后，其他组的相对顺序应保持。
5. 在组内添加动作、批量添加应用并指定目标组；
   编辑器新建草稿组后取消，应不生成动作或草稿组。
6. 回归键盘/手势/子动作/面板选择器，分类标题不能被选为动作，
   搜索结果单选及批量选择应返回正确动作；原有上下文限制应生效。
7. 检查窄屏、较大字体下的底栏、分组长名称与新增编辑器分组行。

预期 syslog：[TypeX][CustomActions] load actions=… groups=… 和 grouped count=…，
只记录数量。编译和包检查不代替安装卸载、冷/热启动及真实 UI 验收。

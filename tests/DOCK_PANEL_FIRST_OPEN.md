# 返回桌面后首次 Dock 面板立即消失

问题：每次从 App 回到桌面，第一次 Dock 手势呼出的面板立即消失；图标与文字间距偏大。

根因：现象尚未通过设备日志定位。源码确认存在三条相关缺口：

- 上滑在 Changed 阶段显示面板，原触摸尚未结束，并主动允许 SpringBoard 背景 pan 同时识别；转场 Hook 随后会无条件关闭面板。
- `frontmostapplicationchanged` 包括返回桌面的变化，旧回调不检查当前前台 App，直接关闭此时新开的面板。
- 初次控制器布局若暂时没有有效 bounds，旧布局把无效几何视为关闭请求。方向通知和未改变配置的布局通知也会无条件关闭。

涉及文件：DXGlobalPanelHooks.xm、DXGlobalPanel.m、DXGlobalPanelGeometry.h、手势面板设置预览及针对性回归测试。

修改边界：Dock 的面板提交时机与背景 pan 仲裁、手势面板的生命周期和文字几何。

实现方案：

1. 三个方向均在 Ended 后提交；面板在下一轮主队列显示，重新检查请求代数、配置、解锁、源窗口、Dock 可见性与几何。取消、新触摸、转场或源状态失效后不重开。
2. 已配置方向对普通背景 pan 请求失败优先关系，不主动请求同时识别；屏幕边缘 pan 仍不设置此关系。关闭／未配置方向及时让出。
3. Darwin 通知按当前状态处理：解锁和返回 Home 保留面板，锁屏和前台 App 激活关闭。前台查询参考本地 PullOver-X 的 `_accessibilityFrontMostApplication`，加入方法存在性、返回 ABI 和异常保护；查询能力不可用时保持保守关闭。
4. 布局用有效根视图 bounds，初始空 bounds 回退到已设置尺寸的 owned window；暂时无有效几何时等待后续布局，不销毁窗口。旧控制器和旧窗口的异步通知不能影响新面板。
5. 物理方向变化和配置未变的 `typeXLayoutChanged` 原地布局，实际 Scene 失活与配置变化仍关闭；过滤其他 Scene 的通知。
6. 手势面板标签紧贴圆形下方 `2 * scale` pt，按实际一／两行文字高度放置，避免固定两行容器将单行文字压低；设置预览同步。

不修改的部分：键盘面板的条目布局、状态栏手势识别、系统动作执行、其他插件代码和旧跨进程协议。

运行时风险：SpringBoard 私有前台查询及真实手势失败关系在 iOS 16／17 上仍需装机验收。没有使用设备日志，不能把源码缺口认定为该设备的唯一根因。

验证步骤：`python3 tests/run-dock-gestures.py` 检查生产 Dock handler 的提交与取消，`python3 tests/run-global-panels.py` 检查生产几何、触摸过滤及直接抽取的通知处理方法；状态栏、注册表和系统控件回归后，在合回 dev 的源码上执行唯一入口 `./build.sh`。

设备验收（iOS 16／17，重启 SpringBoard 后及热启动均执行）：

1. 进入任意 App，返回桌面，立即从 Dock 中缝上滑超过 48pt 再松手，面板应保留；连续重复至少 5 次。
2. 短划、斜划、反向、多指或取消不显示；左右面板在松手后仅显示一次；返回桌面后首次与后续行为一致。
3. 面板显示后点关闭／外部空白、打开 App、锁屏、进入切换器，正常关闭；重新返回桌面能打开。
4. 检查 70%／100%／120% 内容大小、3／4／5 列、单行及两行名称，无重叠或裁切，设置预览一致。
5. Dock 图标点击、长按、排序及 Dock 外系统手势正常；关闭／未配置方向不拦截。

诊断只写 syslog：`trigger request=…`、`presentation cancelled request=…`、`open … origin=dockgesture`、`interrupted reason=switcher-transition`、`close reason=… age=…`。本次不读取设备日志，真机核心功能、冷／热启动和真实仲裁均未验证。
